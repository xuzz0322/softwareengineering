# 吴宪光 分工合作与讲解指南

岗位：前端与交互。负责用页面展示一条清楚的学生操作流程，并说明前端与后端如何配合。建议讲解约 4 分钟，在 常鹂沣 介绍总体需求后进行。

## 1. 负责什么

负责三角色导航、课程卡、搜索筛选、主选备选、课表展示、成绩表单、人员弹窗以及错误反馈。前端使用 HTML/CSS/JavaScript，业务服务由 C++ 提供。

| 打开文件或页面 | 讲解重点 |
|---|---|
| frontend/index.html | 页面入口与资源加载 |
| frontend/styles.css | 布局、课程卡、表单和响应式规则 |
| app.js 的 api、loadData | 同源请求、会话和 CSRF、数据加载 |
| courseCards、selectionBar | 课程信息与数量限制提示 |
| scheduleView、action | 编辑状态、保存草稿和提交 |
| gradesView、userModal | 角色业务表单与错误反馈 |

## 2. 分工合作

从常鹂沣 获取用户流程和业务提示要求；从常鹂沣 获取人员接口，从谭赛 获取登录、选课、授课和成绩接口，从徐振泽 获取关课及计费接口；逐项核对方法、字段和错误码。吴宪光 主责三角色页面与界面验收；与徐振泽 核对示例数据和学期状态。发现乱码时先对照接口值，发现数据不显示时先核对响应结构，不要直接修改页面文案掩盖问题。

前端发现业务拒绝后，应记录账号、页面、输入、请求及响应，再按模块交给常鹂沣（人员）、谭赛（选课教学）或 徐振泽（关课计费）定位。教学时间或初始报名数据改变后，要重新确认演示路线，避免现场选择出冲突组合。

## 3. 推荐演示路线

以下路线以原始演示数据为前提。先确认学期开放、student01 没有需要保留的现场编辑；如果现有数据库已变更，先与徐振泽 准备单独的演示环境。

使用 student01 登录，初始密码 Campus2026!。账号有程序设计基础、数据结构的通过成绩，可用于先修演示。

| 步骤 | 页面操作 | 讲解重点 |
|---|---|---|
| 1 | “学习概览”进入“课程目录” | 当前学期、账号身份和课程入口 |
| 2 | 搜索“软件工程”后清空搜索 | 搜索、学院筛选、先修、教师、时间与容量 |
| 3 | 主选软件工程 201、数据库系统 01 班 202、计算机网络 203、科技写作 207 | 四门主选；科技写作暂时无教师，为后续补位准备 |
| 4 | 依次备选概率论 204、学术英语 205 | 两门备选的顺位有意义 |
| 5 | 保存草稿，查看“我的课表” | 新草稿不占座，状态是草稿 |
| 6 | 提交课表，再查看状态 | 后端通过校验后才是正式报名 |
| 7 | 打开“学期成绩” | 只展示本人已结束学期成绩 |

201 等编号用于讲解者核对教学班，不要求界面直接显示内部 ID。选择数据库系统时核对班号 01，避免误选与软件工程冲突的 02 班。

可以口头说明异常场景；时间充足且已经排练时，再尝试将主选调整为包含编译原理，触发先修未满足。演示失败后恢复原选择，确保最终正式提交仍是上述补位案例。

## 4. 讲解应该落在哪里

课程卡讲“信息如何帮助决策”：名称、时间、费用、先修和名额。课表页讲“显示状态和报名状态的区别”：选择了不代表提交了，保存修改草稿也不代表撤回了原报名。

提交按钮讲“客户端与服务端的职责”：前端提醒数量和重复选择，服务端重新校验先修、冲突和容量。页面刷新人数不能预留座位，别人抢先提交时本次仍可能被拒绝。

代码只需展示 api 如何统一发送请求、action 如何区分草稿与提交、scheduleView 如何表达状态。无需逐行解释样式。人员页面由常鹂沣 开场演示，教师页面由谭赛、关课计费页面由徐振泽 接着演示，避免四个人重复点击同一页面。

## 5. 必须注意

- 更换账号前退出当前账号；同一浏览器普通标签页共享 Cookie，不能靠开多个标签页隔离三种身份。
- 编辑后切换账号可能丢失未保存内容，先完成提交或放弃修改。
- 不把“页面没有按钮”说成权限安全；直接调用接口仍由 C++ 拒绝越权。
- 草稿、实际报名和最终课表不是同一状态，讲解文字要准确。
- 不要提前点教务“关闭选课”，否则后续不能继续选退课或调整授课。
- 新增学生没有预置先修成绩，不适合直接照搬 student01 的计算机课程组合。
- 现有完整浏览器验收尚未完成，正式讲解前必须实际排练；未排练的步骤不要声称已经通过。

## 6. 常见追问

**为什么提交时还要校验一次？** 页面人数可能过时；最终容量与规则以服务端事务检查为准。

**中文乱码如何定位？** 固定标签正常、接口动态字段乱码，说明应检查导入或存储编码；当前 SQL 显式使用 utf8mb4，并有中文精确断言。

**保存草稿后是否占名额？** 新草稿不占；已有正式报名的修改草稿保留原报名，重新提交成功才替换。

## 7. 交接给谭赛

结束时明确告知：“student01 已提交三门有教师主选和一门无教师的科技写作，第一备选是概率论。下面由后端部分解释校验和权限，最后由教务关闭时观察补位。”

## 8. 当前页面设计与交互验收重点

现行界面名称为“校园选课系统”，蓝色主题由 `frontend/theme.css` 覆盖基础样式。展示时可以指出侧栏按角色变化、课程目录提供关键词和学院筛选、课程卡展示时间/学分/人数、课表页分别显示编辑选择与实际报名。对窄屏可展示横向导航、课程卡按钮和表格区域滚动；这些是应人工核对的重点，不因 CSS 已编写就宣称已经完成视觉验收。

吴宪光 的交付还包括错误反馈的解释：先修、冲突或容量错误来自后端最终校验；页面能提前提示，但不能替代提交事务。人员弹窗的毕业日期和授课资格随角色切换，成绩表单留空项不会作为空成绩提交。讲解完学生流程后，告诉 谭赛 已提交的班次和备选顺位，确保后续代码讲解及 徐振泽 的补位演示使用同一数据状态。
