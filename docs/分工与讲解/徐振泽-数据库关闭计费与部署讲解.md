## 3. 数据库讲解重点

## 5. 关课和计费现场路线

此路线必须建立在演示初始状态及 吴宪光 指定提交上。已有业务数据的环境应先备份并核对，不能为了重演直接删除数据卷。

1. 用 admin 登录。人员模块已由常鹂沣 演示，不重复讲解；先定位 level 及关闭接口，说明如何读取正式报名和上次提交备选。
2. 进入“选课管理”，指出科技写作无教师、概率论当前已有两名学生。
3. 解释预期：科技写作取消，student01 按第一备选补入概率论，人数从二到三。
4. 确认所有人的选课和授课演示结束后，执行“关闭本学期选课”。
5. 查看关闭结果及“计费记录”，说明计费生成与财务送达是两个步骤；后台投递后再刷新送达状态。
6. 退出教务，登录 student01 查看最终课表，确认概率论替换科技写作、不能再选退课。

新建数据库的学期 2 已有五名学生正式报名，201/202/203 各五人、205 三人；student01 按上述路线提交后，204 由两人补到三人，共五个班开课、六名学生计费。当前已关闭的演示库保留学期 2 历史，新开放的学期 3 使用对应的 401/402/403/407 主选与 404/405 备选；未提交 student01 时有四个班达到开班条件。现场金额和班级数量仍须按实际数据核对。

## 6. 部署操作与注意事项

在工程目录执行：

```sh
sh scripts/setup.sh
docker compose up -d --build
docker compose ps
```

打开 http://localhost:8080。普通停止使用 docker compose down，保留数据卷。不要在答辩中使用 down -v 重置演示环境。

如需用 Navicat 查看 MySQL，连接 127.0.0.1:3307，账号 `registration`，密码取本机 `.env` 的 `DB_PASSWORD`。数据库端口只绑定本机；讲解时不要投屏显示 `.env` 或复制密码到幻灯片。

自动化测试使用 sh scripts/test.sh，运行在 course-registration-tests 项目及 18080 端口，会清理专用测试卷。运行完整测试需要启动时间，现场优先展示已归档日志，确需现场执行应预留时间。

备份和恢复并不是同一项能力：当前有备份及局部修复记录，但完整恢复演练尚未完成。原题 500/2000 并发、长期可用性、真实 Ingres 和财务系统也尚未验收。

## 7. 常见追问

**数据库是不是 MariaDB？** 服务端是 MySQL 8.4，C++ 使用兼容 MySQL 协议的 MariaDB C 连接器，连接器名称不代表数据库服务端。

**为什么重启后新 SQL 没自动导入？** 初始化 SQL 只在新数据卷初始化时执行；已有数据库需要按迁移方案增量导入。

**如何保证关闭后不漏账？** 最终课表与 outbox 同事务保存，发送失败仍保留任务；接收端按事件键去重。
