# 常鹂沣 分工合作与讲解指南

岗位：组长、需求与人员管理后端。核心任务是说明项目解决什么问题、四个人如何配合、哪些结果已经验证。本文用于分工和答辩准备，不替代个人工作总结。

## 1. 负责什么

负责梳理三类用户、八个主要用例、关键规则和项目边界；维护开发计划、需求追踪及全组报告；组织接口和验收范围的核对。常鹂沣 同时主责学生/教授资料 CRUD、资格维护和人员模块测试，必须能展示对应 C++ 代码。谭赛 提供公共鉴权，徐振泽 维护数据库结构。

需要掌握的规则包括四主选两备选、最多十人、最终不足三人取消、无教师取消、先修和时间冲突、关课后计费，以及四项权限限制。区分“课程”和“教学班”：学生报名的是具体教学班，同一课程不同班次仍不能重复选择。

## 2. 与谁配合

| 合作对象 | 常鹂沣 提供什么 | 对方反馈什么 | 交接时核对什么 |
|---|---|---|---|
| 谭赛 后端 | 用例、权限矩阵、异常条件 | 可实现规则、接口和业务限制 | 草稿语义、关课顺序、错误码 |
| 吴宪光 前端 | 操作流程、页面必须表达的信息 | 页面入口、提示和操作障碍 | 页面文字是否与真实报名一致 |
| 徐振泽 数据库测试 | 每项需求的验收条件 | 测试结果、数据规模、部署限制 | 文档数字与实际日志一致 |

发生需求变更时，按“规则变化—接口或数据影响—页面变化—回归检查—文档更新”交接。不要让四个人分别修改自己理解的规则。

## 3. 讲解顺序与时间

建议全组按 常鹂沣→ 吴宪光→ 谭赛→ 徐振泽→ 常鹂沣 收尾，约 15 分钟。常鹂沣 开场与人员模块约 3 分钟，结束总结约 30 秒，避免开场耗尽时间。

| 顺序 | 打开哪里 | 讲什么 |
|---|---|---|
| 1 | README 的技术与运行说明 | C++17 后端、Web 前端、MySQL 8.4；浏览器访问 8080 |
| 2 | 需求分析中的权限矩阵 | 学生、教授、Registrar 各自可以操作什么 |
| 3 | 设计文档的架构图 | 浏览器到 C++，再到数据库；计费由后台投递 |
| 4 | 开发计划的四人分工 | 常鹂沣 需求与人员后端，谭赛 鉴权与选课教学，吴宪光 前端与界面测试，徐振泽 数据库与关闭计费及部署 |
| 5 | 人员管理页面及 service.cpp 的 maintain_user、admin/users | 只允许 Registrar；展示日期/唯一性校验、停用和历史记录保留；查看表单后取消，避免改变演示数据 |

## 4. 可以怎样讲

开场可表述为：“项目面向学生选课、教授教学和教务管理。学生提交课表后，系统检查先修、冲突和容量；教务关闭选课时再处理取消、补位和最终计费。实现采用 C++、网页前端和 MySQL，下面按一次完整业务流程展示。”

人员模块重点讲：“这里先检查 Registrar，再验证输入及唯一性，最后在事务内修改。停用保留历史记录并撤销会话；存在当前报名或授课时不能停用。人员接口和对应测试由常鹂沣 负责。”

介绍权限时重点讲：“角色权限决定能调用哪类功能，对象归属决定能操作哪一份课表或哪一个教学班。这两层都由后端检查。”

衔接 吴宪光 时说：“接下来从学生选择课程开始，先看页面如何表达主选、备选和正式报名。”徐振泽 结束后收尾：“当前自动化覆盖场景已通过，人工界面和生产规模验证仍按测试计划继续推进。”

## 5. 注意事项

- 不把“保存草稿”说成正式报名；已提交后保存修改草稿仍保留旧报名。
- 不把模拟财务称为真实扣款；不把 MySQL 目录称为真实 Ingres 接入。
- 不把 81 项 API 检查加 12 项规则断言说成 93 个完整端到端用例，两者测试层次不同。
- 六周表是计划，不是实际考勤；岗位分工不等于已认定的贡献率。
- 统一数字：30 门课程、秋季 30 个班、春季 2 个历史班、60 名学生、12 名教授、1 名教务。
- 教务关闭选课安排在最后；提前关闭会使 吴宪光 和 谭赛 无法继续展示本学期修改。

## 6. 常见追问

**为什么还要备选？** 主选班级可能在关课时因无教师被取消，系统按顺位尝试用备选补足；备选不保证一定成功，还要检查先修、冲突及容量。

**四个人如何避免各做各的？** 以需求、接口和数据库约定交接，变更同时更新对应页面、测试与文档，再用同一场景验证完整结果。

**项目是否完全完成？** 主要业务实现和所列自动化检查完成；浏览器完整验收、生产压力、恢复演练和真实外部联调尚未完成，按报告如实说明。

## 7. 上场前检查

先用 admin 展示人员表单并取消，不改密码、不增删演示所用账号；退出后交 吴宪光 登录 student01。确认 吴宪光、谭赛、徐振泽 的演示顺序与账号；确认架构图能显示；核对测试报告引用的是 2026-09-23 的 81 项记录；确定 徐振泽 最后才执行关课；每个人准备一句交接语，减少重复介绍技术栈。

## 8. 工作完成后交什么

常鹂沣 应交付能定位到具体接口的人员管理说明、需求与权限矩阵、人员模块正常及越权测试场景，以及全组文档的一致性检查结果。核验人员模块时，用 Registrar 添加或编辑一名演示人员，再用学生或教授身份尝试同类操作，说明服务端拒绝且原数据保持。现场可以只展示已归档证据，避免增加临时人员影响演示数据。

需要把人员“删除”准确表述为停用：历史成绩及关联记录保留，仍有关联报名或授课时操作会被拒绝。介绍组长职责时，说明如何把字段、页面提示、数据库约束和测试同步起来；不要把全组测试数量说成 常鹂沣 的个人测试数量。
