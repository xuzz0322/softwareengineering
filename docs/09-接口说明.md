# REST 接口说明

基路径 `/api`，JSON UTF-8。同源 Cookie 会话；登录返回 `csrf`，后续写请求必须带 `X-CSRF-Token`。角色与学生身份取自会话，不接受客户端冒充。

## 1. 状态码

200 成功；400 输入不合法；401 未登录/凭据错误；403 角色、归属或 CSRF 不通过；404 数据不存在；409 业务冲突；415 非 JSON 写入；429 登录限速；503 服务暂时不可用。错误结构：`{"error":"中文说明"}`。

## 2. 接口表

| 方法 | 路径 | 角色 | 请求/响应说明 |
|---|---|---|---|

| GET | /offerings | 登录 | semester、offerings、courses；学生附 passed_courses，教师附 qualifications |
| GET | /schedule | 学生 | 直接返回课表对象，未创建时 status=EMPTY |
| PUT | /schedule | 学生 | primary、alternates、submit |
| DELETE | /schedule | 学生 | 删除本人当前课表并释放名额 |
| GET | /report-card | 学生 | 本人已完成学期成绩数组，学期名称字段为 semester |
| GET | /teaching | 教师 | 本人全部学期教学班数组 |
| PUT | /teaching | 教师 | offerings ID 数组，替换本学期授课安排 |

## 3. 典型请求

登录：

```json
{"username":"student01","password":"Campus2026!"}
```

提交课表（PUT）：

```json
{"primary":[201,202,203,204],"alternates":[205,206],"submit":true}
```

`submit=false` 允许少于四主选两备选。新草稿不占名额；保存已有课表的修改草稿保留原正式报名和上次提交的备选。重新提交成功才替换报名；删除课表释放名额。响应直接包含 primary、alternates、status、enrolled，不套 schedule 层。enrolled 表示实际报名教学班编号。

成绩（PUT）：

```json
{"grades":[{"student_id":101,"grade":"A"},{"student_id":103,"grade":"B"}]}
```

只传本次评分的学生；未传学生保持原成绩。传入空字符串属于非法成绩，前端自动省略留空项。

新建学生：

```json
{"username":"student05","password":"Campus2026!","role":"STUDENT","name":"测试同学","birth_date":"2005-01-01","ssn":"DEMO-S005","department":"计算机学院","graduation_date":"2027-06-30"}
```

修改时仍需 username、name、department、birth_date；学生需 graduation_date。password 留空或省略表示保留原密码。教师创建/修改可带 `qualifications:[1,2,3]`。编辑不能改变角色。

## 4. 财务协议

`BILLING_URL` 指定接收端。C++ 使用 POST，认证 Header 为 `X-Billing-Key`；接收方按 `event_key` 幂等。任意 2xx 为送达，非 2xx 或超时触发重试。

```json
{"event_key":"tuition-2-101","student_id":101,"semester_id":2,"amount_cents":90000,"schedule":[{"offering_id":201,"title":"软件工程","fee_cents":90000}]}
```

schedule 展示最终课程明细；上例为最终仅保留一门课程的情况，金额为全部最终课程费用合计。演示端 `POST /internal/demo-billing` 仅在 `DEMO_BILLING=1` 时开启，要求相同密钥，记录于 billing_receipts，不执行真实支付。

## 5. 权限约束

| 操作 | 服务端约束 |
|---|---|
| 查看、保存、提交、删除课表 | 仅 STUDENT，数据库条件固定为当前会话用户 ID；查询参数或 JSON 中的 student_id 指向他人时返回 403 |
| 调整教学班授课 | 仅 PROFESSOR，只能调整本人班级或认领有资格且未分配教师的班级；其他教师的班级拒绝认领（409） |
| 查看名册、录入成绩 | 仅班级所属教授；成绩还须满足学期已结束、学生确在班内。学生和 Registrar 均无录入权限（403） |
| 新增、修改、停用学生资料 | 仅 REGISTRAR；学生不能修改自己的资料，教授也不能修改学生资料（403） |

权限以服务器会话关联的数据库角色为准，请求中的 role、professor_id 等字段不能授予权限。所有写请求还需有效 CSRF。关闭选课后的系统结算属于受控业务流程，不提供教务任意代改学生课表的入口。
