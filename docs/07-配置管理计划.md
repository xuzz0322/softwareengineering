# 配置管理计划

徐振泽 负责配置库、数据库及结算部署，常鹂沣 审核基线并维护人员模块，谭赛 维护鉴权和选课教学模块，吴宪光 维护前端。各成员提交本模块测试和说明，徐振泽 汇总归档。

## 1. 配置项

源代码、SQL 迁移、种子数据、CMake、Dockerfile、Compose、测试、README、课程文档、第三方许可证纳入版本管理。密码 `.env`、数据库卷、构建目录、缓存和临时日志不入库。最终测试证据可在评审核验后归档到交付包。

## 2. 基线与变更

建议阶段标签 `requirements-v1`、`design-v1`、`iteration-1`、`acceptance-v1`。Git 尚未初始化时，交付文件并不等于已有版本历史；团队自行建立仓库并记录真实提交，不能补造协作历史。

需求变更记录编号、提出原因、影响用例/数据库/接口、负责人、评审决定和回归结果。修改模型必须新增迁移或明确演示重置说明；不能对实际数据库直接执行清库重建。

## 3. 环境与依赖

C++ HTTP 依赖 cpp-httplib 0.18.3，JSON 依赖 nlohmann/json 3.11.3，头文件纳入仓库。镜像使用 MySQL 8.4、Debian bookworm-slim，补丁标签可随仓库更新；正式发布应记录实际镜像 digest，保证字节级可复现。OpenSSL 和连接器通过 Debian 官方包获取。

应用配置：DB_HOST、DB_PORT、DB_USER、DB_PASSWORD、DB_NAME、DEMO_PASSWORD、BILLING_KEY、BILLING_URL、DEMO_BILLING、BIND_HOST、PORT、FRONTEND_DIR、COOKIE_SECURE。Compose 本地服务只开放 127.0.0.1。

## 4. 数据与回退

修改源代码前保留已验证版本。回退程序不等于回退数据库；DDL 变化需要单独回退方案。课程演示数据库需要重置时必须明确确认它没有需要保留的数据。

建议使用 `mysqldump` 备份 `registration` 与 `legacy_catalog`，备份前限制敏感数据访问，恢复后检查账号、报名数量、最终课表和 outbox 状态。备份/恢复方案当前为计划，未伪称已经做过恢复演练。

## 5. 交付检查

- 从新数据库卷启动成功。
- 固定版本头文件与许可证完整。
- README 启动步骤可执行。
- 测试脚本只清理专用测试项目。
- `.env` 不进入共享交付包。
- 测试结果、已知限制和配置版本与实际一致。

## 6. 当前配置快照

交付目录提供“校园选课系统-源码配置库.zip”，保存当前 C++、前端、SQL、测试、部署配置、文档和第三方头文件许可证。档内 CHECKSUMS.sha256 按相对路径记录文件摘要，用于检查快照完整性。快照不包含 .env、数据库卷、数据库备份、构建缓存和临时服务日志。

解压后按 README 执行 scripts/setup.sh 与 docker compose up -d --build；新环境按顺序执行三个初始化 SQL。现有数据库不会因 Compose 重启自动运行新增 SQL，应按变更方案备份后增量导入，不能为应用更新直接删除数据卷。

当前已做数据库备份和局部数据修复，但完整备份恢复演练尚未执行。快照不是 Git 提交历史，后续由团队建立仓库并保留真实变更记录。
