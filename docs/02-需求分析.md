# 需求分析说明书

版本 1.1。需求依据为选课系统设计题目及课程设计要求。

## 1. 业务背景与边界

学校以新的客户端/服务器选课系统替换旧系统。学生在校园网络中选课和查询成绩，教师认领课程、查看名册和录入成绩，教务维护人员并结束选课。

系统不负责维护遗留课程目录，也不负责真实支付。前端采用 PPT 允许的 Web 形式。MySQL 替代不可用的遗留实验环境；`legacy_catalog` 只读模拟目录，财务接收端为演示适配。

## 2. 术语

| 概念 | 含义 |
|---|---|
| Course 课程 | 课程基本信息，如代码、名称、学分、先修关系 |
| Offering 教学班 | 某课程某学期某班次，含教师、教室、星期、节次 |
| Schedule 课表 | 一名学生在一个学期的主选和备选安排 |
| Primary 主选 | 提交成功后占用名额的课程，最多四门 |
| Alternate 备选 | 不占用名额，关闭时按顺位尝试补入 |
| Roster 名册 | 某教学班已报名学生列表 |
| Report Card 成绩单 | 本人已结束学期的课程与成绩 |
| Registrar 教务 | 唯一可以维护学生和教师资料的角色 |

## 3. 权限与角色

| 行为 | 学生 | 教师 | 教务 |
|---|---|---|---|
| 查看课程目录 | 是 | 是 | 是 |
| 维护本人课表 | 是 | 否 | 否 |
| 查看本人成绩 | 是 | 否 | 否 |
| 选择本人授课安排 | 否 | 是 | 否 |
| 查看本人教学班名册、录入成绩 | 否 | 是 | 否 |
| 维护学生/教师/教师资格 | 否 | 否 | 是 |
| 关闭选课、查看计费、触发重试 | 否 | 否 | 是 |
| 写入课程目录 | 否 | 否 | 否（外部系统职责） |

浏览器按钮权限只是交互辅助，全部限制由 C++ 后端再次检查。课表和成绩接口根据登录用户取数据，若查询参数或 JSON 显式指定他人 student_id，则返回 403；实际数据条件始终取当前会话用户。

## 4. 功能需求和验收

| 编号 | 需求 | 验收条件 |
|---|---|---|
| FR-01 | 登录/退出 | 错误密码拒绝；退出会话失效；角色由数据库决定 |
| FR-02 | 课程目录 | 显示教师、学院、先修、学分、收费、时间、报名数 |
| FR-03 | 创建/调整/删除课表 | 只能操作本人；提交需四主选两备选；新草稿不占位，修改草稿保留原报名 |
| FR-04 | 提交校验 | 教学班开放、有容量、先修通过、主选无时间冲突、课程不重复 |
| FR-05 | 满员提醒 | 目录每 15 秒刷新；主选变满提示；提交事务再校验并拒绝 |
| FR-06 | 选择授课 | 只可认领具备资格且无人认领的班级；不能改别人的；时间不冲突 |
| FR-07 | 名册与成绩 | 教师只见本人班级；仅已结束学期；A/B/C/D/F/I，可跳过或更正 |
| FR-08 | 查询成绩 | 学生只见本人成绩；无记录显示空态；接口禁止缓存 |
| FR-09 | 人员维护 | 教务增删改学生/教师，编号唯一，日期有效，删除确认 |
| FR-10 | 关闭选课 | 正在处理选课则拒绝；取消无教师、备选补位、最终取消不足三人 |
| FR-11 | 财务通知 | 依据最终课表计算整数分金额；失败重试；重复接收不重复入账 |
| FR-12 | 选退课时间 | 在 OPEN 状态且开放日期内才可更改；关闭后不能再修改 |

## 5. 核心用例

### UC-01 登录

前置：处于登录页面。主流程：输入账号和密码，校验密码哈希，建立两小时会话并返回角色和 CSRF 令牌。异常：错误凭据返回 401，超过登录尝试速率返回 429。后置：成功登录或状态不变。

### UC-02 选课

前置：学生登录；当前学期在选退课期间。主流程：展示目录；选四主选两备选；提交；后端校验；替换原课表并保存报名。备选不占位。异常：缺先修、满员、时间冲突显示具体课程及原因；数据库事务回滚原报名。替代流程：保存草稿（保留原正式报名并标记 DRAFT）；删除课表需确认并释放名额。后置：完整成功或不改变已有数据。

草稿规则补充：已提交课表点击“保存草稿”只保存待提交的修改，原报名与上次提交的备选保留；重新提交成功后才替换，删除课表则释放名额。临时浏览/编辑但未保存不改变服务器数据。

### UC-03 选择授课

前置：教师已登录且当前学期开放。主流程：只展示教师资格范围内课程；选择/取消；验证资格、认领人和时间冲突；一次事务保存。异常：其他教师已认领返回 409；无授课资格返回 403；时间冲突返回 409；无符合课程显示空态。失败保持原安排。

### UC-04 录入成绩

前置：本人曾教授的已结束学期班级。主流程：选班，展示学生，按学号录入 A/B/C/D/F/I；空白跳过；保存。异常：非本人班级、学生不在名册、无效等级、当前学期未结束均拒绝；一批成绩原子保存。

### UC-05 查看成绩

前置：学生登录。主流程：查询当前身份已完成学期报名与成绩；按学期和课程显示。成绩尚未录入显示“暂未录入”。无记录时显示空态，不展示其他学生成绩。

### UC-06/07 维护学生/教师

前置：教务登录。录入姓名、身份编号、学院，学生还需生日和毕业日期；教师需生日和授课资格。新增分配数据库 ID；账号、身份编号唯一。编辑前加载记录；删除须确认。不存在返回 404。有当前报名或授课安排时阻止删除，先解除关联；人员删除采用 active=0 的停用方式，撤销登录会话，保留历史报名和成绩，这是比原题更明确的删除约束。

### UC-08 关闭选课

前置：教务登录且本学期尚未关闭。尝试取得选课写锁，若存在正在处理的事务立即拒绝。读取已提交课表；取消无教师课程；按学生编号、备选顺位尝试补到四门；跳过满员、未满足先修、冲突和无教师备选；最终取消不足三人的班级并移除报名；将课表设 FINAL、学期设 CLOSED；按最终金额写计费 outbox。任意数据库错误则回滚。后台发送财务；不可用时持续重试。

## 6. 非功能需求

| 原题指标 | 本工程方案 | 验收状态/限制 |
|---|---|---|
| 多用户同时操作 | 16 个 HTTP 工作线程，MySQL 事务和跨进程锁 | 已设计并发验证；具体结果见测试报告 |
| 中央 2000、本地 500 并发用户 | 后续连接池、写锁粒度优化和压力测试 | 本工程未宣称达到 |
| 目录延迟 ≤10 秒 | 60 秒缓存，数据库连接/读写超时各 5 秒 | 单独阶段超时不等于端到端硬截止，未完全验收 |
| 80% 事务 ≤2 分钟 | 本机功能流程计时 | 生产容量负载下待测 |
| 24×7，停机≤10% | Compose 健康检查、自动重启 | 无长期可用性实测 |
| 成绩保密 | 身份、角色、归属校验和 no-store | 自动化验证；对外部署需 HTTPS |
| Windows 桌面界面 | 按 PPT Web 许可改为现代浏览器 | 不支持 Windows 95/98 |

## 7. 数据与假设

同学期教学周视为重合，用星期和闭区间节次判定冲突。通过成绩为 A/B/C/D；I、F 和空值不算先修通过。每学期一份课表，同一课程多个班次只能选一个。报价单位为整数分，学生最终计费额是存活主选教学班课程费用之和。

原题步骤未清楚说明不足三人的暂定班级何时移出课表；本实现保留到补位之后再取消，与原题第 4 步“some may have been added as a result of leveling”保持一致。此解释须经团队/教师确认后采用，不伪称唯一解释。

## 8. 四项强制权限验收

| 编号 | 约束 | 攻击或异常请求 | 服务端预期 |
|---|---|---|---|
| SEC-01 | 学生不得修改他人课表 | 在 JSON 或 URL 指定他人 student_id，尝试读取、提交或删除 | 403；双方课表及报名保持 |
| SEC-02 | 教授不得修改他人教学班 | 认领已由其他教授负责的班级，或请求他班成绩接口 | 认领冲突 409；名册或成绩越权 403；原授课与成绩保持 |
| SEC-03 | 只有教授可以录入成绩 | 学生或 Registrar 请求成绩接口，伪造 role 字段 | 403；教授本人还须通过班级归属、学期及名册校验 |
| SEC-04 | 只有 Registrar 可以修改学生信息 | 学生本人、其他学生或教授请求学生资料新增、更新、停用 | 403；原资料及启用状态保持 |

拒绝越权必须发生在业务修改前，不能依靠前端隐藏按钮。系统自动关课结算作为 Registrar 触发的受控用例执行，不等于开放任意修改他人课表的权限。
