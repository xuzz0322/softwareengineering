# 测试计划

版本 1.1；常鹂沣 负责人员与权限测试，谭赛 负责鉴权、选课、授课、成绩和并发测试，吴宪光 负责页面与交互验收，徐振泽 负责关课、计费及数据库测试并组织全量回归。缺陷由所属模块负责人修复，徐振泽 不包办全部测试。

## 1. 目标和分层

验证课程设计业务正确性、角色边界、事务原子性、容量约束和计费恢复。测试分为纯 C++ 规则测试、真实 MySQL API 集成测试、浏览器人工交互与布局验收、后续性能和故障测试。

API 测试使用独立 `course-registration-tests` 项目及 18080 端口，测试结束清除其卷。禁止对真实课程数据库运行测试脚本。演示数据库保留在另一项目中。

## 2. 环境和数据

Docker Compose 启动 MySQL 8.4 与 C++17 Release 服务；测试驱动 Python 3 标准库。浏览器计划包含 Chrome/Edge 桌面以及 390 px 窄屏。

初始数据：60 名学生、12 名教授、1 名教务；春秋两学期；30 门课程、32 个教学班（春季 2 个、秋季 30 个）；两名学生已提交秋季课表。并发测试临时创建十二学生，再移除。所有数据均为虚构演示数据。

## 4. 执行和证据

`sh scripts/test.sh` 先构建并执行 CTest，再启动隔离环境执行 `tests/integration.py`。输出包括每项 PASS 和总数量；任何断言失败非零退出。结果保存在 `output/integration-results.txt`，失败时服务日志写入 `output/test-services.log`。

人工用例记录浏览器版本、视口、步骤、截图、预期与实际，未执行须写“未执行”，不能仅根据代码判断通过。

## 5. 缺陷与退出条件

阻断缺陷包括不能初始化/登录、越权、并发超额、数据丢失、错误收费。核心自动化测试必须通过且阻断缺陷清零；浏览器和生产性能未验证时作为明确的交付限制，不能计为通过。

缺陷记录包括发现条件、影响、根因、修改、回归结果、责任成员与对应提交。课程报告只采用真实测得的数据。
